# Instructions for coding agents

## Scope and architecture

This is research infrastructure, not a production security system. Keep the
`src/jspace_oversight` package modular: configuration/path/provenance utilities,
model loading, lenses, evaluation schemas, and deliberately minimal future
`agents` and `oversight` boundaries. Put executable entry points in `scripts/`,
cluster launchers in `slurm/`, and CPU unit tests in `tests/`. Do not add web
apps, databases, orchestration frameworks, or speculative agent implementations.

## Coding and tests

- Support Python 3.11+ and the `src/` packaging layout.
- Use typed, small functions and public upstream interfaces.
- Keep imports side-effect free; no downloads or model loading at import time.
- Run `ruff check .`, `ruff format --check .`, and `pytest` for every change.
- Keep default tests CPU-only. Mark and separate any future GPU integration test.
- Add tests for configuration/schema/serialization and numeric boundary logic.

## Scientific reproducibility

- Store explicit settings in YAML and snapshot them into run metadata.
- Record Git SHA/dirty state, resolved model revision, versions, random seed,
  hardware/job identifiers, prompt count, layers, runtime, memory, and artifacts.
- Preserve unavailable facts as null. Never invent, round, or silently infer a
  result. Never silently change a layer, prompt corpus, position, seed, budget,
  or other experimental setting.
- Distinguish historical reports from results generated by the current commit.
- Describe lens rankings as uncalibrated vocabulary readouts, not intent or risk.
- Avoid label leakage: use only information available at intervention time.

## Data, checkpoints, and security

Keep weights, `.pt` checkpoints, caches, raw datasets, trajectories, logs,
credentials, and sensitive user data outside Git. Keep Hugging Face credentials
in a protected path separate from Scratch model caches. Do not vendor or nest
clones of Jacobian Lens, AgentDojo, or other upstream repositories. Do not enable
Git LFS without explicit authorization. Run the sensitive-file check and inspect
the staged diff before committing.

## Git and remote execution

Make focused changes; do not overwrite unrelated user work. Do not commit, push,
open issues/PRs, SSH to Skipjack, install remote packages, submit/cancel jobs, or
alter remote environments without explicit authorization. GPU work belongs in a
Slurm allocation, never a login node. Large outputs go to Scratch, and only small
reviewable metadata/summaries may return to Git.

## Mac-to-Skipjack wrappers

For explicitly authorized Skipjack work from a Mac, use only the versioned
commands in `scripts/cluster/`; do not construct a direct `ssh` command. Read-only
status, job, log, and artifact inspection may be run when the user asks to inspect
Skipjack. `pull.sh` and every `submit.sh` invocation require explicit user
authorization because they change remote or scheduler state. The submission
wrapper exposes only smoke jobs and intentionally excludes pilot fitting. Never
cancel jobs, submit a pilot, edit remote files directly, or alter the remote
environment through these wrappers without separate authorization.
